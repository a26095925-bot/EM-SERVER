# Roblox-Style Game Backend (FastAPI + Cloudflare R2 + bcrypt)

## Render deployment

У цьому репозиторії `server.py` і `requirements.txt` лежать у корені. У Render залиште **Root Directory порожнім**, задайте Build Command `pip install -r requirements.txt` і Start Command:

```text
uvicorn server:app --host 0.0.0.0 --port $PORT
```

Файл `.python-version` фіксує Python 3.12: нові версії Pydantic у зафіксованих залежностях можуть не мати готового `pydantic-core` для Python 3.14, через що Render намагається зібрати Rust-пакет у середовищі без доступного Cargo cache.

Після деплою відкрийте кореневу адресу сервісу. У JSON мають бути `"status":"online"` і `"multiplayer_websocket":true`. Це підтверджує, що Render запустив саме версію з маршрутом мультиплеєра. HTTP 403 на WebSocket не завжди означає помилку токена: FastAPI також може відхилити handshake, якщо маршрут `/ws/{place_id}` відсутній. Якщо прапорець відсутній або дорівнює `false`, перевірте вибраний GitHub-репозиторій, гілку `main`, останній успішний deploy і що Root Directory порожній.

### Перевірка WebSocket

Клієнт підключається до `wss://<домен>/ws/<place_id>?token=<JWT>`. Для діагностики можна виконати handshake з будь-яким 32-символьним ID та навмисно недійсним токеном. У поточному застосунку очікується HTTP `403` (маршрут знайдено, токен відхилено). HTTP `404` означає, що запит потрапив на іншу/старішу версію застосунку або інший сервіс. `GET /` зі статусом `200` сам по собі не перевіряє WebSocket.

Render Web Services підтримують WebSocket-з'єднання; окремий перемикач увімкнення WebSocket не потрібен. Переконайтеся, що клієнт використовує `wss://` для HTTPS-домену. Кімнати зараз зберігаються в пам'яті одного процесу, тому мультиплеєр не синхронізується між кількома інстансами сервера.

Цей сервер забезпечує:
1. Безпечну реєстрацію та авторизацію користувачів з хешуванням паролів (**bcrypt**).
2. Захист запитів через **JWT токени**.
3. Збереження та завантаження створених гравцями плейсів у хмару **Cloudflare R2** без бази даних (всі акаунти та плейси зберігаються як JSON у вашому бакеті).

Дані кожного плейса включають шари (до 64), спавн, налаштування швидкості, стрибка та гравітації, біг, відскок від стін, Baseplate і висоту смерті. Налаштування перевіряються та повертаються під час завантаження; старі плейси отримують значення за замовчуванням.

Авторизовані `/api/stats/me` і `/api/stats/death` зберігають смерті та запуски плейсів (ідемпотентні події смерті мають `event_id`). `/api/places/{id}/play` рахує запуски, `/api/places/{id}/like` перемикає вподобання, а `/api/friends` і `/api/friends/{request,accept,remove}` керують друзями. Лічильники зберігаються в записі плейса, а статистика й дружні зв'язки — у JSON у R2 або локальному сховищі. Блокування захищає операції лише всередині одного процесу; для кількох інстансів потрібне сховище з транзакціями.

## Змінні середовища для Render.com (Environment Variables):

У панелі вашого сервісу на Render (`Environment` -> `Add Environment Variable`) додайте:
* `R2_ACCOUNT_ID`: `4cf18f6b81f018297ba7018547ad6005`
* `R2_BUCKET_NAME`: `aient`
* `R2_ACCESS_KEY_ID`: *(Ваш R2 Token Access Key)*
* `R2_SECRET_ACCESS_KEY`: *(Ваш R2 Token Secret Key)*
* `JWT_SECRET`: *(Будь-який довгий секретний рядок для підпису токенів)*

### Де взяти R2 Keys у Cloudflare:
1. Зайдіть у Cloudflare Dashboard -> **R2 Object Storage**.
2. Праворуч натисніть **Manage R2 API Tokens**.
3. Натисніть **Create API Token**, надайте права **Object Read & Write**.
4. Скопіюйте `Access Key ID` та `Secret Access Key` в змінні Render.
